# WorkBuddy2API 本地版：启动与配置教程

本教程与配套快捷方式位于部署目录的 `使用入口` 文件夹。文中所有路径都以**部署目录**为基准，你可以把整个目录放在任意盘符下。

所有协议入口共享同一个账号池；模型前缀（`cn:` / `global:`）决定路由到国内版还是国际版，不会把国内积分用于国际模型。国内和国际积分在工作台概览、账号页分别汇总。

## 1. 日常只需要这几个文件

| 文件 | 用途 |
| --- | --- |
| `启动服务.cmd` | 启动网关、协议兼容层、管理后台并打开浏览器；已运行时复用现有进程 |
| `停止服务.cmd` | 停止以上三个服务，保留账号与配置 |
| `重启服务.cmd` | 先停止再启动，适合修改配置后使用 |
| `检查服务.cmd` | 检查服务、账号数量与模型列表，不发送对话 |
| `复制API密钥.cmd` | 从当前 `config.json` 读取密钥并复制到剪贴板 |
| `刷新接入信息.cmd` | 重新生成密钥文本与客户端配置示例；修改密钥后使用 |
| `打开管理后台.cmd` | 打开 7864 工作台，不启动服务 |
| `打开配置教程.cmd` | 用浏览器打开本教程的 HTML 版 |
| `API测试.cmd` | 交互输入一条真实请求，选择国内／国际和协议，可能消耗积分 |
| `API密钥.txt` | 一行完整网关密钥，可直接复制（安装时生成，仅存本机） |
| `admin-access.txt` | 管理后台、API 地址、完整密钥及接入信息（安装时生成） |
| `配置示例` | 分国内和国际的 Codex TOML、Claude JSON、OpenAI JSON 示例 |

可以把快捷方式放到桌面，但要保留 `使用入口` 文件夹在部署目录内，脚本依赖这个相对位置。

重启电脑后双击 `启动服务.cmd`。安装脚本会注册一个看门狗计划任务，掉线 1 分钟内自动拉起；但如果电脑关机或睡眠，自动任务不会执行。CMD 启动窗口关闭后后台服务继续运行，停止请用 `停止服务.cmd`。遇到「任务正在运行」的提示时，等当前任务结束再停。

## 2. 地址和密钥怎么填

| 使用场景 | 填写地址 | 说明 |
| --- | --- | --- |
| 管理后台 | `http://127.0.0.1:7864/` | 浏览器打开；本机后台没有独立账号密码 |
| OpenAI Chat 客户端 | `http://127.0.0.1:7863/v1` | OpenAI SDK、Cherry Studio、普通 Chat 接入 |
| Codex / Responses 客户端 | `http://127.0.0.1:8787/v1` | 必须使用支持 Responses 的 8787 入口 |
| Claude Code / Anthropic SDK | `http://127.0.0.1:8787` | **不加 /v1**，SDK 自行追加 /v1/messages |
| 旧后台地址 | `http://127.0.0.1:8787/admin/` | 自动跳转至 7864 |

两个 API 入口使用同一个网关密钥：双击 `复制API密钥.cmd`，或读取 `API密钥.txt`。**这不是 WorkBuddy 账号的 accessToken。** 如需放行旧客户端密钥，可把哈希写进 `compat/config.json` 的 `legacy_api_keys`，该表默认是空数组。

完整端点：

```text
GET  http://127.0.0.1:7863/v1/models
POST http://127.0.0.1:7863/v1/chat/completions
GET  http://127.0.0.1:8787/v1/models
POST http://127.0.0.1:8787/v1/chat/completions
POST http://127.0.0.1:8787/v1/responses
POST http://127.0.0.1:8787/v1/messages
```

Chat 和 Responses 鉴权为 `Authorization: Bearer <API密钥>`；Messages 兼容层也支持 `x-api-key: <API密钥>`。Base URL 不要填写成完整的 `/chat/completions` 地址。

网关默认只监听 `127.0.0.1`。其他电脑、手机、Docker 容器和 WSL 内的 `127.0.0.1` 指向各自环境，不能直接照抄当作宿主地址。

## 3. 国内和国际模型选择

| 版本 | 推荐默认模型 |
| --- | --- |
| 国内 | `cn:deepseek-v4.1-flash` |
| 国际 | `global:fast-model`、`global:default-model` |
| 国际 GPT | `global:gpt-6-sol`、`global:gpt-6.1-sol`、`global:gpt-6-luna` |

国内推荐 `cn:deepseek-v4.1-flash`：在同类评测里它是「判分全过 + 解码最快 + 单轮积分最省」三项同时最好的一档。对照 `cn:fast-model` 当前路由到 `glm-5.3-flash`（能力低一档、单价更高），`cn:deepseek-v4-pro` 单价约为它的 8 倍且在困难题上会截断输出。评测脚本与完整对照表见 `docs/model-notes.md`。

`cn:default-model` 不可用：国内上游没有这个别名，会返回 `11102 model [default-model] service info not found`。国际侧的 `global:default-model` 仍然可用，两者不要混用。

GPT-6.1 Sol 初次用 `max_tokens=32` 测试会返回空正文且 `finish_reason=length`；设置 `max_tokens=256`、`reasoning_effort=low` 后正常。上限过低会让思考在正文前就花完预算，短任务建议从 256 起。可直接参考 `配置示例/codex-gpt6.1-sol.toml`。

`cn:` 和 `global:` 是网关路由前缀，必须随模型名一起填写。没有前缀的裸模型名走国内版。

**模型名必须写，不能留空。** 网关不会替你选默认模型：空模型名会原样发给上游并返回 `11102 model [] service info not found`（实测 503）。`auto` 是国内侧的自动路由别名，实测落点是一个更贵的模型，不适合当日常默认。

其他模型到后台「连接测试 → 读取服务模型列表」查看，或在部署目录执行：

```powershell
$cfg = Get-Content '.\config.json' -Raw -Encoding UTF8 | ConvertFrom-Json
$headers = @{ Authorization = 'Bearer ' + $cfg.api_key }
(Invoke-RestMethod 'http://127.0.0.1:7863/v1/models' -Headers $headers).data.id
```

返回列表含静态模型名；出现在列表里不代表每个账号都能调用。先测试一条，再配置为客户端默认。账号轮转发生在同一版本内，普通客户端请求不能保证固定使用某个账号。

## 4. CC Switch 配置

在 [CC Switch](https://github.com/farion1231/cc-switch) 中选择对应应用，新增两个自定义供应商，分别命名为 `WorkBuddy 国内`、`WorkBuddy 国际`。

**Codex 供应商：**

1. Base URL 填 `http://127.0.0.1:8787/v1`，密钥填当前 API Key。
2. 协议设为 Responses，配置中使用 `wire_api = "responses"`。
3. 国内默认模型填 `cn:deepseek-v4.1-flash`；国际填 `global:fast-model`。
4. 参考 `配置示例/codex-cn.toml` 或 `codex-global.toml`，模板使用 `WORKBUDDY_API_KEY` 环境变量。
5. 保存并启用对应供应商，完全退出并重开 Codex。模型前缀决定版本。

**Claude Code 供应商：**

1. Base URL 填 `http://127.0.0.1:8787`，**不加 /v1**。
2. 密钥填当前 API Key；选择 Anthropic / Messages 协议。
3. 国内的 Sonnet / Haiku / Opus 槽位都填 `cn:deepseek-v4.1-flash`（国内没有可用的 Opus 替代）；国际相应使用 `global:` 前缀。
4. 这些是客户端别名映射，并不表示上游实际提供原生 Claude Sonnet / Opus。
5. 参考 `配置示例/claude-cn.json`、`claude-global.json`，保存、启用并重开 Claude Code。

## 5. Codex 手动接入

先备份 `~/.codex/config.toml`，把模板中的供应商段**合并**到现有配置，保留其他项目、权限和插件配置；不要用示例覆盖整个文件。

```toml
model = "global:fast-model"
model_provider = "workbuddy_global"

[model_providers.workbuddy_global]
name = "WorkBuddy Global"
base_url = "http://127.0.0.1:8787/v1"
env_key = "WORKBUDDY_API_KEY"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false
```

在部署目录的 PowerShell 里设置用户环境变量：

```powershell
$cfg = Get-Content '.\config.json' -Raw -Encoding UTF8 | ConvertFrom-Json
[Environment]::SetEnvironmentVariable('WORKBUDDY_API_KEY', $cfg.api_key, 'User')
$env:WORKBUDDY_API_KEY = $cfg.api_key
```

然后完全退出并重开 Codex 和终端。修改网关密钥后要重复这一步。国内版改用 `codex-cn.toml`。如果 CC Switch 管理 Codex，请在供应商里调整，避免手动配置被下次切换覆盖。

当前官方 Codex 使用 Responses 协议；本地兼容层是 HTTP/SSE，不支持 Responses WebSocket。参见[官方配置参考](https://developers.openai.com/codex/config-reference)。

## 6. Claude Code 手动接入

可以把模板的 `env` 字段**合并**进 `~/.claude/settings.json`，保留已有设置。也可以在会话内临时设置：

```powershell
$cfg = Get-Content '.\config.json' -Raw -Encoding UTF8 | ConvertFrom-Json
$env:ANTHROPIC_BASE_URL = 'http://127.0.0.1:8787'
$env:ANTHROPIC_AUTH_TOKEN = $cfg.api_key
Remove-Item Env:ANTHROPIC_API_KEY -ErrorAction SilentlyContinue
$env:ANTHROPIC_DEFAULT_SONNET_MODEL = 'global:fast-model'
$env:ANTHROPIC_DEFAULT_OPUS_MODEL = 'global:default-model'
$env:ANTHROPIC_DEFAULT_HAIKU_MODEL = 'global:fast-model'
claude --model 'global:fast-model'
```

此方式只影响当前终端及其启动的进程。国内版把所有 `global:` 换成 `cn:`。如果之前启用了 Bedrock、Vertex 或其他网关，需要先在客户端切到自定义 Anthropic 供应商。

[Claude Code 模型配置文档](https://code.claude.com/docs/en/model-config)。本地 Messages 接口已验证，原生 Claude 专属功能不保证都能由转换层实现。

## 7. Cherry Studio / OpenAI Chat 客户端

新增「OpenAI 兼容」供应商：

| 字段 | 值 |
| --- | --- |
| API 地址 | `http://127.0.0.1:7863/v1` |
| API Key | 从 `复制API密钥.cmd` 获取 |
| 国内模型 ID | `cn:deepseek-v4.1-flash` |
| 国际模型 ID | `global:fast-model` |

Cherry Studio 会补全请求路径；若你的版本会重复拼接 `/v1`，地址改填 `http://127.0.0.1:7863`。最终请求应为**一个** `/v1/chat/completions`。其他客户端若支持协议选择，选 OpenAI Chat Completions。

保存后手动添加模型或读取列表，开一个新会话验证。初次先关闭联网搜索、图像等额外功能，确认纯文本对话正常后再测工具功能。

## 8. PowerShell / Python 调用

PowerShell 国际版 Chat 示例：

```powershell
$cfg = Get-Content '.\config.json' -Raw -Encoding UTF8 | ConvertFrom-Json
$body = @{ model='global:fast-model'; messages=@(@{role='user'; content='请给出整理项目 README 的三个建议。'}); stream=$false; max_tokens=128 } | ConvertTo-Json -Depth 8
$reply = Invoke-RestMethod 'http://127.0.0.1:7863/v1/chat/completions' -Method Post -Headers @{Authorization=('Bearer '+$cfg.api_key)} -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body)) -TimeoutSec 150
$reply.choices[0].message.content
```

国内版把 model 改成 `cn:deepseek-v4.1-flash`。`使用入口\api-example.py` 只用 Python 标准库，不需要安装 SDK：

```powershell
& '.\使用入口\API测试.cmd'
# 或
python '.\使用入口\api-example.py' --realm global --protocol chat --prompt '请给出整理项目 README 的三个建议。'
```

`--protocol` 可选 `chat`、`responses`、`messages`；`--realm` 可选 `cn`、`global`。只看模型列表用 `--models`，不发送对话。示例自动读取当前网关密钥，默认回复上限 128 Token；这只是回复上限，输入与上游额外开销仍会计费。

## 9. 账号、积分与定时任务

账号管理页把国内和国际账号分成两个资源池，可搜索和按版本筛选。每行的「参与调用」可单独纳入或排除账号，分组标题的勾选框可全选该版本。该选择会保存并在重启后保留；未勾选的账号不会被普通 API 请求选中。

取消勾选只影响普通 API 调用，不影响自动签到、凭据刷新、余额查询或其他已启用的自动任务。系统检测到凭据失效时仍会禁用相应账号。

添加账号时选择正确版本，生成官方登录链接，完成 **CLI 授权** 后返回页面等待自动保存。只登录到账号首页不代表 CLI 授权完成。也支持导入 `.json` / `.info`；旧国内凭据的毫秒有效期在副本中会转成秒。

积分数据来自上游余额查询，工作台会定时刷新，也可手动「查询积分」。国内和国际余额分别汇总；查询失败的账号显示未知，不计入已知余额。两个版本的积分不能互相转移。

默认排程（北京时间）：签到／旅行 09、21 点；国内活跃上报 10 点；Token 保活 22 点；开学季 12 点；夜猫子 01 点。页面可独立修改时间与开关，保存时会重启网关。

国际版每日签到接口目前返回「签到活动未开启或已过期」，不能把国际账号送到国内签到入口。国际版的每日活跃奖励与国内签到不同：官方要求在客户端开始对话，反代请求是否计入、奖励是否到账由上游决定。[官方奖励页面](https://www.workbuddy.ai/pricing/)。

「国际版日常对话任务」是每账号独立配置、默认关闭。启用后北京时间 06:00–07:00 随机执行，默认回复上限 64 Token，每账号每天至多一次成功执行；只有明确的模型不可用拒绝才允许换一次模型；超时、结果未知或奖励未到账不重试；错过窗口不补发；失败或服务中断会暂停，需要检查后手动恢复，恢复也不重发当天已尝试的任务。输出保存在 `output\daily-tasks`。

日常任务默认「自动省积分」：读取该账号的实时模型目录，优先当前免费或实测零扣费的模型，否则选不超过 0.34 倍的最低已知倍率模型。免费活动已过期时，0 倍标签不视为免费依据。

国际版模拟活跃事件上报已停用。随机时间只用于分散负载，不用于规避识别，也不保证获得奖励。官方禁止制造虚假互动。[官方使用政策](https://www.workbuddy.ai/document/acceptable-use-policy)。

## 10. 提示词与高级配置

后台「接入与提示词」可选择透传客户端提示词（默认），或自定义系统提示词。自定义模式会替换客户端的 system / developer 提示词，因此会影响 Codex、Claude Code 的工作指令；日常使用建议保留透传。

`config.json` 是真实配置。手动编辑前备份，保持合法 JSON，改完用 `重启服务.cmd`。常用字段：

| 字段 | 作用 |
| --- | --- |
| `api_key` | 网关密钥，变更后重启并刷新接入信息，更新客户端 |
| `listen` | 监听地址，默认 `127.0.0.1:7863` |
| `schedule.*_enabled` / `*_hours` | 各任务开关与 0–23 整点列表 |
| `global.enabled` | 是否提供国际版路由 |
| `pool.max_in_flight` | 每账号同时请求上限，默认 3 |
| `pool.breaker_threshold` | 连续失败多少次进入熔断 |
| `pool.expiring_soon` | 快过期积分优先消耗的窗口，默认 7 天 |
| `upstream.timeout_seconds` | 上游请求超时秒数，默认 120 |
| `session_sticky.enabled` | 同一会话尽量保持同一账号 |
| `prompt.mode` | `passthrough` 或 `custom` |
| `features.sanitize_blacklist_fingerprints` | 出站字段清洗开关 |
| `upstash.url` / `upstash.token` | 可选：把池状态镜像到 Upstash Redis |

端口 7863、7864、8787 在启动器、工作台与兼容层之间是硬编码关联的，只改 `listen` 会导致工作台和兼容层失联，需要同时改 `workbench/server.py` 的 `PORT`、`compat/server.py` 的 `uvicorn.run(port=...)` 以及各启动脚本。

## 11. 常见问题

| 现象 | 处理 |
| --- | --- |
| 后台无法打开／Connection refused | 先双击 `启动服务.cmd`；确认三个端口都通（`检查服务.cmd`） |
| 401 | 重新复制当前网关密钥；旧密钥默认已不放行 |
| 404 / Responses 不存在 | Codex 用 `8787/v1`；Claude Code 用 `8787` 根地址，检查是否重复 `/v1` |
| 端口被占用 | 检查是否还有另一份部署在跑；不要随意结束陌生进程 |
| `all accounts unavailable` / 503 | 查看对应版本的账号是否冷却、暂停、凭据过期或积分不足 |
| 国际模型用了国内积分 | 检查实际发出的 model 是否带 `global:`；裸名默认国内 |
| 模型列表有但调用失败 | 列表不保证套餐权限；国内先用 `cn:deepseek-v4.1-flash`、国际先用 `global:fast-model` 验证 |
| `11102 model [...] service info not found` | 模型名写错或该账号不服务此模型；换回推荐模型 |
| `11140 request illegal` | 上游 chat 通道封禁，与 token 无效不同（计费接口仍可用）；先重登，无效则该号只能换号 |
| `14018 Credits exhausted` | 该账号积分耗尽，chat 通道本身是通的 |
| `11-128` | 请求没被识别为官方客户端；用网关而不是手写裸 POST 探测 |
| CLI 授权一直未完成 | 重新打开当前生成的链接，确认完成 CLI 授权而非只进入首页 |
| 任务没执行 | 确认开关、账号版本、时间窗口，以及电脑保持运行 |
| 日常任务失败后停止 | 查看该账号错误并解决，然后点「恢复后续排程」；当天不重复执行 |
| 兼容层启动失败 | 运行 `install.ps1` 重建 `runtime\venv`，确认 `fastapi`/`uvicorn`/`httpx` 已装 |
| 改了 Go 代码没生效 | 必须 `build.ps1` 重新编译并重启网关，改源码不会自动生效 |

日志位于 `logs`：`server.stderr.log`、`workbench.stderr.log`、`compat.stderr.log`。`compat.log` 会记录完整请求体，属于敏感文件，不要在排查时全量 grep 或粘贴到外部。

## 12. 备份与迁移

重要数据：`auths`、`config.json`、`data`、`compat/config.json`、`使用入口`。先停止服务，再复制备份。不要删掉 `auths` 后重启。

迁移到新机器：把整个部署目录复制过去，删掉 `runtime` 后在目标机重新运行 `install.ps1`（会重建 Go/Python 环境并重新编译），账号与配置会保留。

`API密钥.txt`、`admin-access.txt`、`配置示例` 里的密钥需要在生成后自行保管；`auths` 含账号凭据。这些文件都在 `.gitignore` 里，不要提交到任何仓库。
