# 工作台说明

`http://127.0.0.1:7864/` 是本项目的本地管理界面。原始网关项目只有 API 和 CLI，工作台是为本地部署新增的一层。

## 页面清单

| 页面 | 主区域 | 主要交互 |
| --- | --- | --- |
| 工作台概览 | 五个指标卡 + 双域积分卡 + 近 7 天用量 + 账号工作区 + 任务日程 | 刷新状态、查询额度、跳转到管理工作台 |
| 账号管理 | CN / Global 两个分组表格 | 搜索、按版本筛选、逐账号启用/停用、添加账号、查询积分 |
| 用量统计 | 四个指标卡 + 趋势图 + 明细表 | 时间区间切换、指标切换、按账号/模型/天查看 |
| 自动任务 | 六类任务卡片 + 国际版日常对话任务 | 修改整点排程与开关、保存、辅助工具、恢复排程 |
| 连接测试 | 请求表单 + 响应面板 | 选模型、读模型列表、发真实请求 |
| 接入与提示词 | 接入信息卡 + 提示词设置卡 | 复制地址/密钥、切换提示词模式、指纹清洗开关 |
| 运行日志 | 一个滚动 pre 区域 | 刷新日志 |

## 账号管理页的语义

这是最容易误解的一页，两个开关含义不同：

- **参与调用**（页面上的复选框）
  存的是 `routing_paused`。取消勾选只把该账号从**普通 API 请求**的候选里排除。
  定时任务（签到、保活、余额查询）照常运行 —— 你的号不会因为不参与路由就断掉凭据续期。

- **系统禁用**（表格里的状态列）
  存的是 `disabled`，由系统写入，原因是凭据失效、被上游吊销等。
  这个不能靠取消勾选来回切；重新登录后勾选「参与调用」会一并清掉它。

把这两个搞混的后果很具体：曾经出现过重新登录后账号永远不可用的情况 —— 因为 `ReviveDisabled` 只被接入在 UI 的「启用」路径上，而重登只替换凭据，`disabled` 标志一直留着。

### 时间字段

表格里有两个时间，含义完全不同：

| 位置 | 含义 |
| --- | --- |
| 「余额查询 MM/DD HH:MM」 | 上一次成功拉到余额的时间。由工作台自动刷新线程约每 30 分钟跑一次 `credits` 任务 |
| 「凭据有效期 YYYY/MM/DD HH:MM」 | access token 的过期时刻 |
| 其下小字「剩余 N 天」 | refresh token 还剩多少天。≤25 天变橙色，表示该考虑重新登录了 |

失效账号会保留上一次成功的余额（标记为 stale），查询失败不清零 —— 否则一次上游抖动会让面板全变空。

### 时区处理

页面所有北京时间都是手算的：`epoch + 8h` 后取 `getUTC*` 字段，**不用 `toLocaleString` / `Intl`**。

原因是实测过：某些浏览器环境下 `toLocaleString(..., {timeZone:'Asia/Shanghai'})` 的行为和 UTC 一样，导致整页时间早 8 小时。手算偏移不依赖浏览器时区数据库，跨环境结果一致。

改这块代码时别把 `Intl` 加回来，包括用量页的日期选择器要谨慎对待。

## 用量统计

数据来源不是单独的埋点，而是**解析网关访问日志**。网关每处理完一个请求写一行：

```
| #230 | 10:21:20 | cn:deepseek-v4.1-flash | stream | 200 | uid=xxxx | TTFB=1782ms | tok=417 | 99.5tok/s | total=4.2s | credit=0.32 |
```

工作台打开时把新行入库（`data/usage-*.json`），页面从入库结果统计。这意味着：

- 日志被重启截断不会丢已入库的数据
- 但如果某段时间服务没跑，那段时间就是空的
- 「积分」列来自 `credit=` 字段；早期日志没有这个字段时显示"仅 N/M 次有积分记录"，不会伪造 0

视图有三种：按账号、按模型、按天。趋势图单日按小时、多日按天。

## 自动任务页

六类任务的开关和整点都存进 `config.json` 的 `schedule` 段。保存会**重启网关**（约 4.4 秒），因为调度器在进程启动时读取配置。

国际版日常对话任务是另一套逻辑：每账号独立配置、默认关闭。启用后在北京时间 06:00–07:00 随机执行一次，每账号每天至多成功一次；失败会暂停需要手动恢复；错过的窗口不补发。

选模型策略默认"自动省积分"：读该账号实时模型目录，优先当前免费或实测零扣费的，否则选不超过 0.34 倍的最低已知倍率模型。查询不到价格就暂停，不会瞎猜。

## 安全模型

工作台没有用户名密码。保护手段是四层叠加：

1. 只监听 `127.0.0.1`
2. 启动时生成随机 `NONCE`，注入 HTML 的 `__TOKEN__`，前端每个请求带 `X-Workbench-Token`
3. `Host` 头必须是 `127.0.0.1:7864` 或 `localhost:7864`（防 DNS rebinding）
4. `Origin` 必须是同源，且 `Sec-Fetch-Site` 不能是 `cross-site`

同样的思路：账号 token 永远不返回浏览器，页面拿到的只有余额和状态。日志接口返回前会 `redact()` 掉已知的 token 和密钥。

**这套机制的前提是本机可信。** 不要把它反向代理到公网或局域网。

## 前端结构

```
workbench/
├── index.html      单页，七个 <section class="page-panel">
├── app.js          全部逻辑，约 40 KB，无构建步骤
├── style.css       主样式（参考自 codebuddy2api）
├── extra.css       本项目增补
└── server.py       后端，标准库 http.server
```

没有前端框架和打包器：修改 `app.js` / CSS 后刷新浏览器即可，`server.py` 每次 GET 都从磁盘重读文件，不需要重启工作台。

## 后端接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/state` | 账号池状态、积分、用量概览 |
| GET | `/api/usage?start=&end=` | 区间用量统计 |
| GET | `/api/models` | 透传网关的实时模型列表 |
| GET | `/api/logs` | 网关日志尾部（已脱敏） |
| POST | `/api/account` | 启用 / 停用账号 |
| POST | `/api/schedules` | 保存六类任务排程（会重启网关） |
| POST | `/api/login/start` / `poll` / `cancel` | OAuth 登录流程 |
| POST | `/api/import` | 导入 `.json` / `.info` 凭据 |
| POST | `/api/daily-tasks` / `/resume` | 国际版日常任务配置 |
| POST | `/api/region/info` / `save` | 国际版地区查询与激活 |
| POST | `/api/action` | 触发 `credits` / `trial` / `task_query` 等 |

所有 POST 都经过 `authorized()` 校验；请求体上限 1 MB。
