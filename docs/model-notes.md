# 模型选择参考

本文记录国内侧默认模型的选型依据与几个容易踩的坑。数据来自本机对上游实测，不代表上游承诺；活动、价格和可用性随时可能变。

## 国内侧默认：`cn:deepseek-v4.1-flash`

在同批候选里它是唯一三项同时靠前的型号：

| 候选 | 判分 | 解码速度 | 单轮积分 |
| --- | --- | --- | --- |
| **`cn:deepseek-v4.1-flash`** | 全过 | 最快 | 最低 |
| `cn:deepseek-v4-pro` | 少过一题（困难题截断） | 约 1/3 速度 | 约 8 倍 |
| `cn:fast-model`（当前落到 glm-5.3-flash） | 少过一题 | 约 1/4 速度 | 约 1.4 倍 |

结论很直接：v4.1-flash 又快又便宜还更准，没有理由用另外两个做日常默认。

### 测量方法上的两个坑

**不要强制模型只输出答案。** 早期评测用"只回复整数"的指令，结果把思维链压没了，同一提示词同一模型多次运行分数在 22–35 之间跳 —— 那是噪声不是能力。正确做法是允许自由推理，只对最后一行 `FINAL:` 判分。

**`max_tokens` 太小会拿到空正文。** 推理段先花预算，`finish_reason=length` 时 `content` 是空字符串。短任务从 200–256 起，别用 16 / 32。

## 国际侧

| 用途 | 模型 |
| --- | --- |
| 日常对话 | `global:fast-model` |
| 通用备选 | `global:default-model` |
| 高推理 | `global:gpt-6.1-sol`（配 `reasoning_effort=low`） |

GPT-6.1 Sol 用 `max_tokens=32` 会返回空正文；`max_tokens=256` + `reasoning_effort=low` 正常。上限不是固定消耗，实测那次总共只用了 36 token。

## 不存在或不该用的名字

| 名字 | 问题 |
| --- | --- |
| `cn:default-model` | 国内上游没有这个别名，返回 `11102 model [default-model] service info not found` |
| 空模型名 | 网关不提供默认值，原样发给上游 → `11102 model [] service info not found`（503） |
| 裸 `auto` | 国内侧的自动路由别名，实测落到一个更贵的型号，不适合做日常默认 |
| 裸模型名（不带前缀） | 默认走国内侧，容易误用国内积分跑国际模型 |

## 前缀规则

- `cn:` → 国内账号池，消耗国内积分
- `global:` → 国际账号池，消耗国际积分
- 无前缀 → 国内

两个版本的积分不能互相转移。看清楚实际发出的 `model` 到底是什么，是排查"积分用错版本"的第一件事。

## 模型列表的局限

`/v1/models` 返回的是**静态名单**，包含所有已知模型名。它不反映：

- 你的账号套餐是否有该模型权限
- 该模型当前是否对你封禁（11140 可按模型粒度生效）
- 当前价格倍率

所以"列表里有"不等于"能调用"。先用推荐模型验证一条真实请求，再改成别的。

## 价格是实时查的

`GET /_manage/model-pricing?uid=...` 拉该账号实时的 Global 模型目录（8 秒超时）。价格发现和模型名发现是分开的两件事：不要用静态倍率表猜成本。

免费标签要看活动是否过期。0 倍率的标签如果关联的促销已经结束，不能当作"免费"依据 —— 自动省积分逻辑对这种情况会暂停而不是盲发。
